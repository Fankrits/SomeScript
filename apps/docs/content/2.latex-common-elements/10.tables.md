# Tables



Tables are a common feature in academic writing, often used to summarize research results. Mastering the art of table construction in LaTeX is therefore necessary to produce quality papers and with sufficient practice one can print beautiful tables of any kind.

Keeping in mind that LaTeX is not a spreadsheet; it makes sense to use a dedicated tool to build tables and then to export these tables into the document. Basic tables are not too taxing, but anything more advanced can take a fair bit of construction; in these cases, more advanced packages can be very useful. However, first it is important to know the basics. Once you are comfortable with basic LaTeX tables, you might have a look at more advanced packages or the [[#Using spreadsheets and data analysis tools|export options of your favorite spreadsheet]]. Thanks to the modular nature of LaTeX, the whole process can be automated in a fairly comfortable way.

## Introduction
LaTeX has built-in support to typeset tables and provides two environments: {{LaTeX/Environment|tabular}} and {{LaTeX/Environment|table}}. To typeset material in rows and columns, the {{LaTeX/Environment|tabular}} environment is needed; the optional {{LaTeX/Environment|table}} environment is a container for floating material similar to {{LaTeX/Environment|figure}}, into which a {{LaTeX/Environment|tabular}} environment may be included.

The {{LaTeX/Environment|table}} environment contains the caption and defines the float for the table, i.e., where in the document the table should be positioned and whether we want it to be displayed centered. The {{LaTeX/Inline|code=\caption}} and {{LaTeX/Inline|code=\label}} commands can be used in the same way as for pictures. For more information about the {{LaTeX/Environment|table}} environment, see the [[#Floating with table|Floating with ''table'']] section.

In any case, the actual content of the table is contained within the {{LaTeX/Environment|tabular}} environment.

## The ''tabular'' environment

The {{LaTeX/Environment|tabular}} environment can be used to typeset tables with optional horizontal and vertical lines. LaTeX determines the width of the columns automatically.

The first line of the environment has the form:
{{LaTeX/Usage|code=
\begin{tabular}[pos]{table spec}
}}

The {{LaTeX/Parameter|table spec}} argument tells LaTeX the alignment to be used in each column and the vertical lines to insert.

The number of columns does not need to be specified as it is inferred by looking at the number of arguments provided. It is also possible to add vertical lines between the columns here. The following symbols are available to describe the table columns (some of them require that the package {{LaTeX/Package|array}} has been loaded):

{| class="wikitable"
| {{LaTeX/Parameter|l}}
| left-justified column
|-
| {{LaTeX/Parameter|c}}
| centered column
|-
| {{LaTeX/Parameter|r}}
| right-justified column
|-
| {{LaTeX/Parameter|p{'width'}<!---->}}
| paragraph column with text vertically aligned at the top
|-
| {{LaTeX/Parameter|m{'width'}<!---->}}
| paragraph column with text vertically aligned in the middle (requires array package)
|-
| {{LaTeX/Parameter|b{'width'}<!---->}}
| paragraph column with text vertically aligned at the bottom (requires array package)
|-
| <code><nowiki>|</nowiki></code>
| vertical line
|-
| <code><nowiki>||</nowiki></code>
| double vertical line
|}

By default, if the text in a column is too wide for the page, LaTeX won’t automatically wrap it. Using {{LaTeX/Parameter|p{'width'}<!---->}} you can define a special type of column which will wrap-around the text as in a normal paragraph. You can pass the width using any unit supported by LaTeX, such as 'pt' and 'cm', or ''command lengths'', such as {{LaTeX/LaTeX|code=\textwidth<!---->}}. You can find a list in chapter [[LaTeX/Lengths|Lengths]].

The optional parameter {{LaTeX/Parameter|pos}} can be used to specify the vertical position of the table relative to the baseline of the surrounding text. In most cases, you will not need this option. It becomes relevant only if your table is not in a paragraph of its own. You can use the following letters:

{| class="wikitable"
|-
| {{LaTeX/Parameter|b}}
| bottom
|-
| {{LaTeX/Parameter|c}}
| center (default)
|-
| {{LaTeX/Parameter|t}}
| top
|-
|}

To specify a font format (such as bold, italic, etc.) for an entire column, you can add {{LaTeX/LaTeX|code=>{\format}<!---->}} before you declare the alignment. For example {{LaTeX/LaTeX|code=\begin{tabular}{ >{\bfseries}l c >{\itshape}r }<!---->}} will indicate a three column table with the first one aligned to the left and in bold font, the second one aligned in the center and with normal font, and the third aligned to the right and in italic. The "array" package needs to be activated in the preamble for this to work.

In the first line you have pointed out how many columns you want, their alignment and the vertical lines to separate them. Once in the environment, you have to introduce the text you want, separating between cells and introducing new lines. The commands you have to use are the following:

{| class="wikitable"
| {{LaTeX/LaTeX|code=&<!---->}}
| column separator
|-
| {{LaTeX/LaTeX|code=\\<!---->}}
| start new row (additional space may be specified after {{LaTeX/LaTeX|code=\\<!---->}} using square brackets, such as {{LaTeX/Parameter|\\[6pt]}})
|-
| {{LaTeX/LaTeX|code=\hline<!---->}}
| horizontal line
|-
| {{LaTeX/LaTeX|code=\newline<!---->}}
| start a new line within a cell (in a paragraph column)
|-
| {{LaTeX/LaTeX|code=\cline{i-j}<!---->}}
| partial horizontal line beginning in column ''i'' and ending in column ''j''
|}

Note, any white space inserted between these commands is purely down to one's preferences. I personally add spaces between to make it easier to read.

### Basic examples

This example shows how to create a simple table in LaTeX. It is a three-by-three table, but without any lines.

{{LaTeX/Example|code=
\begin{tabular}{ l c r }
  1 & 2 & 3 \\
  4 & 5 & 6 \\
  7 & 8 & 9 \\
\end{tabular}
|render=
<math>\begin{array}{lcr} 1 & 2 & 3 \\ 4 & 5 & 6 \\ 7 & 8 & 9 \\ \end{array}</math>
}}

Expanding upon that by including some vertical lines:

{{LaTeX/Example|code=
\begin{tabular}{ l {{!}} c {{!}} r }
  1 & 2 & 3 \\
  4 & 5 & 6 \\
  7 & 8 & 9 \\
\end{tabular}
|render=
<math>\begin{array}{l|c||r} 1 & 2 & 3 \\ 4 & 5 & 6 \\ 7 & 8 & 9 \\ \end{array}</math>
}}

To add horizontal lines to the very top and bottom edges of the table:

{{LaTeX/Example|code=
\begin{tabular}{ l {{!}} c {{!}} r }
  \hline			
  1 & 2 & 3 \\
  4 & 5 & 6 \\
  7 & 8 & 9 \\
  \hline  
\end{tabular}
|render=
<math>\begin{array}{l|c||r}\hline 1 & 2 & 3 \\ 4 & 5 & 6 \\ 7 & 8 & 9 \\ \hline \end{array}</math>
}}

And finally, to add lines between all rows, as well as centering (notice the use of the center environment - of course, the result of this is not obvious from the preview on this web page):

{{LaTeX/Example|code=
\begin{center}
  \begin{tabular}{ l {{!}} c {{!}} r }
    \hline
    1 & 2 & 3 \\ \hline
    4 & 5 & 6 \\ \hline
    7 & 8 & 9 \\
    \hline
  \end{tabular}
\end{center}
|render=
<math>\begin{array}{l|c||r}\hline 1 & 2 & 3 \\ \hline  4 & 5 & 6 \\ \hline  7 & 8 & 9 \\ \hline \end{array}</math>
}}

{{LaTeX/Example|code=
\begin{center}
  \begin{tabular}{ {{!}} l {{!}} c {{!}} r }
    \hline
    1 & 2 & 3 \\ \hline
    4 & 5 & 6 \\ \hline
    7 & 8 & 9 \\
    \hline
  \end{tabular}
\end{center}
|render=
<math>\begin{array}{|l||c|||r}\hline 1 & 2 & 3 \\ \hline  4 & 5 & 6 \\ \hline \hline 7 & 8 & 9 \\ \hline \end{array}</math>
}}

\begin{tabular}{{{!}}r{{!}}l{{!}}}
  \hline
  7C0 & hexadecimal \\
  3700 & octal \\ \cline{2-2}

### Text wrapping in tables

LaTeX's algorithms for formatting tables have a few shortcomings. One is that it will not automatically wrap text in cells, even if it overruns the width of the page. For columns that will contain text whose length exceeds the column's desired width, it is recommended that you use the {{LaTeX/Parameter|p}} attribute and specify the desired width of the column (although it may take some trial-and-error to get the result you want). For a more convenient method, have a look at [[#The tabularx package|The tabularx package]], or [[#The tabulary package|The tabulary package]].

Instead of {{LaTeX/Parameter|p}}, use the {{LaTeX/Parameter|m}} attribute to have the lines aligned toward the middle of the box or the {{LaTeX/Parameter|b}} attribute to align along the bottom of the box.

Here is a simple example. The following code creates two tables with the same code; the only difference is that the last column of the second one has a defined width of 5 centimeters, while in the first one we didn't specify any width. Compiling this code:

{{LaTeX/Usage|code=
\documentclass{article} 
\usepackage[english]{babel}

\begin{document}

Without specifying width for last column:
\begin{center}
    \begin{tabular}{{{!}} l {{!}} l {{!}} l {{!}} l {{!}}}
    \hline
    Day & Min Temp & Max Temp & Summary \\ \hline
    Monday & 11C & 22C & A clear day with lots of sunshine.
    However, the strong breeze will bring down the temperatures. \\ \hline
    Tuesday & 9C & 19C & Cloudy with rain, across many northern regions. Clear spells 
    across most of Scotland and Northern Ireland, 
    but rain reaching the far northwest. \\ \hline
    Wednesday & 10C & 21C & Rain will still linger for the morning. 
    Conditions will improve by early afternoon and continue 
    throughout the evening. \\
    \hline
    \end{tabular}
\end{center}

With width specified:
\begin{center}
    \begin{tabular}{ {{!}} l {{!}} l {{!}} l {{!}} p{5cm} {{!}}}
    \hline
    Day & Min Temp & Max Temp & Summary \\ \hline
    Monday & 11C & 22C & A clear day with lots of sunshine.  
    However, the strong breeze will bring down the temperatures. \\ \hline
    Tuesday & 9C & 19C & Cloudy with rain, across many northern regions. Clear spells 
    across most of Scotland and Northern Ireland, 
    but rain reaching the far northwest. \\ \hline
    Wednesday & 10C & 21C & Rain will still linger for the morning. 
    Conditions will improve by early afternoon and continue 
    throughout the evening. \\
    \hline
    \end{tabular}
\end{center}

\end{document}
}}

You get the following output:

### Manually broken paragraphs in table cells
Sometimes it is necessary to not rely on the breaking algorithm when using the {{LaTeX/Parameter|p}} specifier, but rather specify the line breaks by hand. In this case it is easiest to use a {{LaTeX/LaTeX|code=\parbox<!---->}}:

{{LaTeX/Usage|code=
\begin{tabular}{cc}
  boring cell content & \parbox[t]{5cm}{rather long par\\new par}
\end{tabular}
}}

Here the {{LaTeX/Parameter|t}} argument controls the placement of the text inside the box. Other allowed values are {{LaTeX/Parameter|c}} for center and {{LaTeX/Parameter|b}} for bottom.

### Space between columns

To tweak the space between columns (LaTeX will by default choose very tight columns), one can alter the column separation: {{LaTeX/LaTeX|code=\setlength{\tabcolsep}{5pt}<!---->}}.
The default value is 6pt.

One can also introduce a horizontal space with hspace like this: {{LaTeX/LaTeX|code=\begin{tabular}{r@{\hspace{1in}<!---->}<!---->rr}<!---->}} There are different options for the hspace [[LaTeX/Lengths|length]].

### Space between rows

Re-define the {{LaTeX/LaTeX|code=\arraystretch<!---->}} command to set the space between rows:
{{LaTeX/Usage|code=
\renewcommand{\arraystretch}{1.5}
}}
Default value is 1.0.

An alternative way to adjust the rule spacing is to add {{LaTeX/LaTeX|code=\noalign{\smallskip}<!---->}} before or after the {{LaTeX/LaTeX|code=\hline<!---->}} and {{LaTeX/LaTeX|code=\cline{i-j}<!---->}} commands:

{{LaTeX/Usage|code=
\begin{tabular}{ {{!}} l {{!}} l {{!}} r {{!}} }
  \hline\noalign{\smallskip}
  \multicolumn{2}{c}{Item} \\
  \cline{1-2}\noalign{\smallskip}
  Animal & Description & Price (\$) \\
  \noalign{\smallskip}\hline\noalign{\smallskip}
  Gnat  & per gram & 13.65 \\
        & each     &  0.01 \\
  Gnu   & stuffed  & 92.50 \\
  Emu   & stuffed  & 33.33 \\
  Armadillo & frozen & 8.99 \\
  \noalign{\smallskip}\hline
\end{tabular}
}}

You may also specify the skip after a line explicitly using glue after the line terminator

{{LaTeX/Usage|code=
\begin{tabular}{ll}
\hline
Mineral & Color \\[1cm]
Ruby & red \\
Sapphire & blue \\
\hline
\end{tabular}
}}

### Other environments inside tables

If you use some LaTeX environments inside table cells, like {{LaTeX/Environment|verbatim}} or {{LaTeX/Environment|enumerate}}:

{{LaTeX/Usage|code=
\begin{tabular}{c c}
	\hline
	\begin{verbatim}
	code
	\end{verbatim}
	& description
 	\\ \hline
\end{tabular}
}}

you might encounter errors similar to
```output
! LaTeX Error: Something's wrong--perhaps a missing \item.
```
To solve this problem, change [[#The tabular environment|column specifier]] to "paragraph" ({{LaTeX/Parameter|p}}, {{LaTeX/Parameter|m}} or {{LaTeX/Parameter|b}}).

{{LaTeX/Usage|code=
\begin{tabular}{m{5cm} c}
}}

### Column specification using <code>>{\cmd}</code> and <code><{\cmd}</code>

The column specification can be altered using the {{LaTeX/Package|array}} package.  This is done in the 
argument of the tabular environment using {{LaTeX/LaTeX|code=>{\command}}} for commands executed right 
''before'' each column element and {{LaTeX/LaTeX|code=<{\command}}} for commands to be executed right
''after'' each column element. 
As an example: to get a column in math mode enter: ```tex" inline\begin{tabular}{>{$}c<{$}}```. 
Another example is changing the font: {{LaTeX/LaTeX|code=\begin{tabular}{>{\small}c}|}} to print the column in a small font.

The argument of the {{LaTeX/LaTeX|code=>|}} and {{LaTeX/LaTeX|code=<|}} specifications must be correctly balanced when it comes to {{LaTeX/LaTeX|code={|}} and {{LaTeX/LaTeX|code=}|}} characters. This means that {{LaTeX/LaTeX|code=>{\bfseries}|}} is valid, while {{LaTeX/LaTeX|code=>{\textbf}|}} will not work and <code>{\textbf{}}</code> is not valid. If there is the need to use the text of the table as an argument (for instance, using the {{LaTeX/LaTeX|code=\textbf|}} to produce bold text), one should use the {{LaTeX/LaTeX|code=\bgroup|}} and {{LaTeX/LaTeX|code=\egroup|}} commands: {{LaTeX/LaTeX|code=>{\textbf\bgroup}c<{\egroup}|}} produces the intended effect. This works only for some basic LaTeX commands. For other commands, such as {{LaTeX/LaTeX|code=\underline|}} to underline text, it is necessary to temporarily store the column text in a box using {{LaTeX/LaTeX|code=lrbox|}}. First, you must define such a box with {{LaTeX/LaTeX|code=\newsavebox{\boxname}|}} and then you can define:

{{LaTeX/Usage|code=
>{\begin{lrbox}{\boxname} }%
l%
<{\end{lrbox}%
  \underline{\unhbox\boxname} }%
 }
}}

This stores the text in a box and afterwards, takes the text out of the box with {{LaTeX/LaTeX|code=\unhbox|}} (this destroys the box, if the box is needed again one should use {{LaTeX/LaTeX|code=\unhcopy|}} instead) and passing it to {{LaTeX/LaTeX|code=\underline|}}. (For LaTeX2e, you may want to use {{LaTeX/LaTeX|code=\usebox{\boxname}|}} instead of {{LaTeX/LaTeX|code=\unhbox\boxname|}}.)

This same trick done with {{LaTeX/LaTeX|code=\raisebox|}} instead of {{LaTeX/LaTeX|code=\underline|}} can force all lines in a table to have equal height, instead of the natural varying height that can occur when e.g. math terms or superscripts occur in the text.

Here is an example showing the use of both {{LaTeX/LaTeX|code=p{...}|}} and {{LaTeX/LaTeX|code=>{\centering}|}} :
```tex
\begin{tabular}{>{\centering}p{3.5cm}>{\centering}p{3.5cm} }
Geometry  & Algebra
\tabularnewline
\hline
 Points & Addition 
\tabularnewline
 Spheres & Multiplication 
\end{tabular}
```

Note the use of {{LaTeX/LaTeX|code=\tabularnewline|}} instead of {{LaTeX/LaTeX|code=\\|}} to avoid a <samp>Misplaced \noalign</samp> error.

### @ and ! expressions

The column separator can be specified with the {{LaTeX/LaTeX|code=@{...}<!---->}} or {{LaTeX/LaTeX|code=!{...}<!---->}} constructs. 

It typically takes some text as its argument, and when appended to a column, it will automatically insert that text into each cell in that column before the actual data for that cell. The {{LaTeX/LaTeX|code=@{...}<!---->}} command kills the inter-column space and replaces it with whatever is between the curly braces. To keep the initial space, use {{LaTeX/LaTeX|code=!{...}<!---->}}. To add space, use {{LaTeX/LaTeX|code=@{\hspace{''width''}<!---->}<!---->}}.

Admittedly, this is not that clear, and so will require a few examples to clarify. Sometimes, it is desirable in scientific tables to have the numbers aligned on the decimal point. This can be achieved by doing the following:

{{LaTeX/Example|code=
\begin{tabular}{r@{.}l}
  3   & 14159 \\
  16  & 2     \\
  123 & 456   \\
\end{tabular}
|render=
<math>\begin{align}3&.14159\\16&.2\\123&.456\end{align}</math>
}}

  \hline
\end{tabular}
}}

### Aligning columns at decimal points using dcolumn
Instead of using @-expressions to build columns of decimals aligned to the decimal point (or equivalent symbol), it is possible to center a column on the decimal separator using the {{LaTeX/Package|dcolumn}} package, which provides a new column specifier for floating point data. See the [http://anorien.csc.warwick.ac.uk/mirrors/CTAN/macros/latex/required/tools/dcolumn.pdf dcolumn package documentation] for more information, but a simple way to use {{LaTeX/Package|dcolumn}} is as follows.
{{LaTeX/Example|code=
\usepackage{dcolumn}
\ldots
\newcolumntype{d}[1]{D{.}{\cdot}{#1} }
%the argument for d specifies the maximum number of decimal places
\begin{tabular}{l r c d{1} }
Left&Right&Center&\mathrm{Decimal}\\
1&2&3&4\\
11&22&33&44\\
1.1&2.2&3.3&4.4\\
\end{tabular}
|render={{Dark mode invert|[[File:LaTeX_example_dcolumn.png|200px]]}}
}}
A negative argument provided for the number of decimal places in the new column type allows unlimited decimal places, but may result in rather wide columns.  Rounding is not applied, so the data to be tabulated should be adjusted to the number of decimal places specified.  Note that a decimal aligned column is typeset in math mode, hence the use of \mathrm for the column heading in the example above.  Also, text in a decimal aligned column (for example the header) will be right-aligned before the decimal separator (assuming there's no decimal separator in the text).  While this may be fine for very short text, or numeric column headings, it looks cumbersome in the example above.  A solution to this is to use the {{LaTeX/LaTeX|code=\multicolumn}} command described below, specifying a single column and its alignment. For example to center the header ''Decimal'' over its column in the above example, the first line of the table itself would be {{LaTeX/LaTeX|code=Left&Right&Center&\multicolumn{1}{c}{Decimal}\\}}

#### Bold text and dcolumn
To draw attention to particular entries in a table, it may be nice to use bold text.  Ordinarily this is easy, but as dcolumn needs to ''see'' the decimal point it is rather harder to do.  In addition, the usual bold characters are wider than their normal counterparts, meaning that although the decimals may align nicely, the figures (for more than 2--3 digits on one side of the decimal point) will be visibly misaligned.  It is however possible to use normal width bold characters and define a new bold column type, as shown below.<ref>{{cite web|url=http://tex.stackexchange.com/questions/118458/decimals-in-table-dont-align-with-dcolumn-when-bolded|title=Decimals in table don't align with dcolumn when bolded|author=D Carlisle|publisher=Stackexchange}}</ref>

{{LaTeX/Example|code=
\usepackage{dcolumn}
%here we're setting up a version of the math fonts with normal x-width
\DeclareMathVersion{nxbold} 
\SetSymbolFont{operators}{nxbold}{OT1}{cmr} {b}{n}
\SetSymbolFont{letters}  {nxbold}{OML}{cmm} {b}{it}
\SetSymbolFont{symbols}  {nxbold}{OMS}{cmsy}{b}{n}

\begin{document}
\makeatletter
\newcolumntype{d}{D{.}{.}{-1} } %decimal column as before
%wide bold decimal column
\newcolumntype{B}[3]{>{\boldmath\DC@{#1}{#2}{#3} }c<{\DC@end} } 
%normal width bold decimal column
\newcolumntype{Z}[3]{>{\mathversion{nxbold}\DC@{#1}{#2}{#3} }c<{\DC@end} } 
\makeatother
\begin{tabular}{l l d}
    Type &M & \multicolumn{1}{c}{N} \\
    Normal & 1 & 22222.222 \\
    Bold (standard)&10 & \multicolumn{1}{B{.}{.}{-1} }{22222.222}\\
    Bold (nxbold)&100 & \multicolumn{1}{Z{.}{.}{-1} }{22222.222}\\
\end{tabular}
\end{document}
|render={{Dark mode invert|[[file:LaTeX example dcolumn bold.png|200px]]}}
}}

== Row specification == 

It might be convenient to apply the same command over every cell of a row, just as for column. Unfortunately the {{LaTeX/Environment|tabular}} environment cannot do that by default.
We will need {{LaTeX/Package|tabu}} instead, which provides the {{LaTeX/LaTeX|code=\rowfont<!---->}} option.

{{LaTeX/Usage|code=
\begin{tabu}{XX}
\rowfont{\bfseries\itshape\large} Header1 & Header2 \\
\hline
Cell2 & Cell2
\end{tabu}
}}

## Spanning

To complete this tutorial, we take a quick look at how to generate slightly more complex tables. Unsurprisingly, the commands necessary have to be embedded within the table data itself.

### Rows spanning multiple columns

The command for this looks like this: {{LaTeX/LaTeX|code=\multicolumn{num_cols}{alignment}{contents}<!---->}}. {{LaTeX/Parameter|num_cols}} is the number of subsequent columns to merge; {{LaTeX/Parameter|alignment}} is either {{LaTeX/Parameter|l}}, {{LaTeX/Parameter|c}}, {{LaTeX/Parameter|r}}, or to have text wrapping specify a width {{LaTeX/LaTeX|code=p{5.0cm}<!---->}} . And {{LaTeX/Parameter|contents}} is simply the actual data you want to be contained within that cell. You can also use {{LaTeX/LaTeX|code=\multicolumn{1}{alignment}{contents}<!---->}} for a single column. In this simple example, the name David Batty is an exception, shifted to the right:

{{LaTeX/Example|code=
\begin{tabular}{ {{!}}l{{!}}l{{!}} }
  \hline
  \multicolumn{2}{{{!}}c{{!}}}{Team sheet} \\
  \hline
  GK & Paul Robinson \\
  LB & Lucas Radebe \\
  DC & Michael Duberry \\
  DC & Dominic Matteo \\
  RB & Dider Domi \\
  MC & \multicolumn{1}{r{{!}}}{David Batty} \\
  MC & Eirik Bakke \\
  MC & Jody Morris \\
  FW & Jamie McMaster \\
  ST & Alan Smith \\
  ST & Mark Viduka \\
  \hline
\end{tabular}
|render=
{{Dark mode invert|[[Image:multicolumn.svg]]}}
}}

### Columns spanning multiple rows

The first thing you need to do is add {{LaTeX/LaTeX|code=\usepackage{multirow}}} to the preamble<ref name="multirow">Package multirow [http://www.ctan.org/tex-archive/macros/latex/contrib/multirow/ on CTAN]</ref>. This then provides the command needed for spanning rows: <code>\multirow{''num_rows''}{''width''}{''contents''}</code>. The arguments are pretty simple to deduce ({{LaTeX/LaTeX|code=*<!---->}} for the ''width'' means the content's natural width).

{{LaTeX/Example|code=
...
\usepackage{multirow}
...

\begin{tabular}{ {{!}}l{{!}}l{{!}}l{{!}} }
\hline
\multicolumn{3}{ {{!}}c{{!}} }{Team sheet} \\
\hline
Goalkeeper & GK & Paul Robinson \\ \hline
\multirow{4}{*}{Defenders} & LB & Lucas Radebe \\
 & DC & Michael Duburry \\
 & DC & Dominic Matteo \\
 & RB & Didier Domi \\ \hline
\multirow{3}{*}{Midfielders} & MC & David Batty \\
 & MC & Eirik Bakke \\
 & MC & Jody Morris \\ \hline
Forward & FW & Jamie McMaster \\ \hline
\multirow{2}{*}{Strikers} & ST & Alan Smith \\
 & ST & Mark Viduka \\
\hline
\end{tabular}
|render=
{{Dark mode invert|[[Image:multirow.svg]]}}
}}

The main thing to note when using {{LaTeX/LaTeX|code=\multirow<!---->}} is that a blank entry must be inserted for each appropriate cell in each subsequent row to be spanned.

If there is no data for a cell, just don't type anything, but you still need the "&" separating it from the next column's data. The astute reader will already have deduced that for a table of <math>n</math> columns, there must always be <math>n-1</math> ampersands in each row (unless {{LaTeX/LaTeX|code=\multicolumn<!---->}} is also used).

### Spanning in both directions simultaneously

Here is a nontrivial example of how to use spanning in both directions simultaneously and have the borders of the cells drawn correctly:

{{LaTeX/Example|code=
\usepackage{multirow}

\begin{tabular}{cc{{!}}c{{!}}c{{!}}c{{!}}c{{!}}l}
\cline{3-6}
& & \multicolumn{4}{ c{{!}} }{Primes} \\ \cline{3-6}
& & 2 & 3 & 5 & 7 \\ \cline{1-6}
\multicolumn{1}{ {{!}}c  }{\multirow{2}{*}{Powers} } &
\multicolumn{1}{ {{!}}c{{!}} }{504} & 3 & 2 & 0 & 1 &     \\ \cline{2-6}
\multicolumn{1}{ {{!}}c  }{}                        &
\multicolumn{1}{ {{!}}c{{!}} }{540} & 2 & 3 & 1 & 0 &     \\ \cline{1-6}
\multicolumn{1}{ {{!}}c  }{\multirow{2}{*}{Powers} } &
\multicolumn{1}{ {{!}}c{{!}} }{gcd} & 2 & 2 & 0 & 0 & min \\ \cline{2-6}
\multicolumn{1}{ {{!}}c  }{}                        &
\multicolumn{1}{ {{!}}c{{!}} }{lcm} & 3 & 3 & 1 & 1 & max \\ \cline{1-6}
\end{tabular}
|render=
{{Dark mode invert|[[Image:multirowandcolumnexample.svg|300px]]}}
}}

The command {{LaTeX/LaTeX|code=\multicolumn{1}{|c|}{...}<!---->}} is just used to draw vertical borders both on the left and on the right of the cell. Even when combined with {{LaTeX/LaTeX|code=\multirow{2}{*}{...}<!---->}}, it still draws vertical borders that only span the first row. To compensate for that, we add {{LaTeX/LaTeX|code=\multicolumn{1}{|c|}{...}<!---->}} in the following rows spanned by the multirow. Note that we cannot just use {{LaTeX/LaTeX|code=\hline<!---->}} to draw horizontal lines, since we do not want the line to be drawn over the text that spans several rows. Instead we use the command {{LaTeX/LaTeX|code=\cline{2-6}<!---->}} and opt out the first column that contains the text "Powers".

Here is another example exploiting the same ideas to make
the familiar and popular "2x2" or double dichotomy:

{{LaTeX/Example|code=
\begin{tabular}{ r{{!}}c{{!}}c{{!}} }
\multicolumn{1}{r}{}
 &  \multicolumn{1}{c}{noninteractive}
 & \multicolumn{1}{c}{interactive} \\
\cline{2-3}
massively multiple & Library & University \\
\cline{2-3}
one-to-one & Book & Tutor \\
\cline{2-3}
\end{tabular}

## Controlling table size

### Resize tables

The {{LaTeX/Package|graphicx}} packages features the command {{LaTeX/LaTeX|code=\resizebox{width}{height}{object}<!---->}} which can be used with {{LaTeX/Environment|tabular}} to specify the height and width of a table. The following example shows how to resize a table to 8cm width while maintaining the original width/height ratio.

{{LaTeX/Usage|code=
\usepackage{graphicx}
% ...

\resizebox{8cm}{!} {
  \begin{tabular}...
  \end{tabular}
}
}}

Resizing table including the caption

{{LaTeX/Usage|code=
\begin{table}[h]
\resizebox{1.4\textwidth}{!}{\begin{minipage}{\textwidth}
\begin{tabular}{r{{!}}c{{!}}c{{!}}}
& \multicolumn{1}{c}{noninteractive}
& \multicolumn{1}{c}{interactive} \\
\cline{2-3}
massively multiple & Library & University \\
\cline{2-3}
one-to-one & Book & Tutor \\
\cline{2-3}
\end{tabular}
\caption[Table caption text]{Table taken from \cite[p.10]{refid} }
\label{table:name}
\end{minipage} }
\end{table}
}}

Alternatively you can use {{LaTeX/LaTeX|code=\scalebox{ratio}{object}<!---->}} in the same way but with ratios rather than fixed sizes:

{{LaTeX/Usage|code=
\usepackage{graphicx}
% ...

\scalebox{0.7}{
  \begin{tabular}...
  \end{tabular}
}
}}

### Changing font size
A table can be globally switched to a different font size by simply adding the desired size command (here: {{LaTeX/LaTeX|code=\footnotesize<!---->}}) in the table scope, which may be after the {{LaTeX/LaTeX|code=\begin{table}<!---->}} statement if you use floats, otherwise you need to add a group delimiter.

{{LaTeX/Usage|code=
{\footnotesize
  \begin{tabular}{{{!}} r {{!}} r {{!}}{{!}} c {{!}} c {{!}} c {{!}}}
      % ...
  \end{tabular}
}
}}

{{LaTeX/Usage|code=
\begin{table}[h]\footnotesize
  \caption{Performance at peak F-measure}
  \begin{tabular}{{{!}} r {{!}} r {{!}}{{!}} c {{!}} c {{!}} c {{!}}}
      % ...
  \end{tabular}
\end{table}
}}

Alternatively, you can change the default font for all the tables in your document by placing the following code in the preamble:

{{LaTeX/Usage|code=
\let\oldtabular\tabular 
\renewcommand{\tabular}{\footnotesize\oldtabular} 
}}

See [[LaTeX/Fonts#Sizing_text|Fonts]] for named font sizes.  The table caption font size is not affected. To control the caption font size, see [[LaTeX/Floats,_Figures_and_Captions#Caption_Styles|Caption Styles]].

It is also possible to change the vertical space between rows using {{LaTeX/LaTeX|code=\renewcommand{\arraystretch}{0.8}<!---->}} before {{LaTeX/LaTeX|code=\begin{tabular}<!---->}}.

## Width and stretching

We keep providing documentation for {{LaTeX/Environment|tabular*}} and {{LaTeX/Environment|tabularx}}.

### The ''tabular*'' environment

This is basically a slight extension on the original tabular version, although it requires an extra argument (before the column descriptions) to specify the preferred width of the table.

{{LaTeX/Example|code=
\begin{tabular*}{0.75\textwidth}{ {{!}} c {{!}} c {{!}} c {{!}} r {{!}} }
  \hline
  label 1 & label 2 & label 3 & label 4 \\
  \hline 
  item 1  & item 2  & item 3  & item 4  \\
  \hline
\end{tabular*}
|render=
{{Dark mode invert|[[Image:LaTeX TabWidth1.svg|right]]}}
}}

However, that may not look quite as intended. The columns are still at their natural width (just wide enough to fit their contents) while the rows are as wide as the table width specified. If you do not like this default, you must also explicitly insert extra column space. LaTeX has ''rubber lengths'', which, unlike others, are not fixed. LaTeX can dynamically decide how long the lengths should be. So, an example of this is the following.

{{LaTeX/Example|code=
\begin{tabular*}{0.75\textwidth}{@{\extracolsep{\fill} } {{!}} c {{!}} c {{!}} c {{!}} r {{!}} }
  \hline
  label 1 & label 2 & label 3 & label 4 \\
  \hline 
  item 1  & item 2  & item 3  & item 4  \\
  \hline
\end{tabular*}
|render=
{{Dark mode invert|[[Image:LaTeX TabWidth2.svg|right]]}}
}}

You will notice the {{LaTeX/LaTeX|code=@{...}<!---->}} construct added at the beginning of the column description. Within it is the {{LaTeX/LaTeX|code=\extracolsep<!---->}} command, which requires a width. A fixed width could have been used. However, by using a rubber length, such as {{LaTeX/LaTeX|code=\fill<!---->}}, the columns are automatically spaced evenly.

### The ''tabularx'' package

This package provides a table environment called {{LaTeX/Environment|tabularx}}, which is similar to the {{LaTeX/Environment|tabular*}} environment except that it has a new column specifier {{LaTeX/Parameter|X}} (in uppercase). The column(s) specified with this specifier will be stretched to make the table as wide as specified, greatly simplifying the creation of tables.

{{LaTeX/Example|code=
\usepackage{tabularx}
% ...

\begin{tabularx}{\textwidth}{ {{!}}X{{!}}X{{!}}X{{!}}X{{!}} }
  \hline
  label 1 & label 2 & label 3 & label 4 \\
  \hline 
  item 1  & item 2  & item 3  & item 4  \\
  \hline
\end{tabularx}
|render=
{{Dark mode invert|[[Image:LaTeX TabXWidth1.svg|450px|right]]}}
}}

The content provided for the boxes is treated as for a {{LaTeX/Parameter|p}} column, except that the width is calculated automatically. If you use the package {{LaTeX/Package|array}}, you may also apply any {{LaTeX/LaTeX|code=>{\cmd}|}} or {{LaTeX/LaTeX|code=<{\cmd}|}} command to achieve specific behavior (like {{LaTeX/LaTeX|code=\centering<!---->}}, or {{LaTeX/LaTeX|code=\raggedright\arraybackslash<!---->}}) as described previously.

Another option is to use {{LaTeX/LaTeX|code=\newcolumntype<!---->}} to format selected columns in a different way. It defines a new column specifier, e.g. {{LaTeX/Parameter|R}} (in uppercase). In this example, the second and fourth column is adjusted in a different way ({{LaTeX/LaTeX|code=\raggedleft<!---->}}):

{{LaTeX/Example|code=
\usepackage{tabularx}
% ...

\newcolumntype{R}{>{\raggedleft\arraybackslash}X}%
\begin{tabularx}{\textwidth}{ {{!}}l{{!}}R{{!}}l{{!}}R{{!}} }
  \hline
  label 1 & label 2 & label 3 & label 4 \\
  \hline 
  item 1  & item 2  & item 3  & item 4  \\
  \hline
\end{tabularx}
|render=
{{Dark mode invert|[[Image:LaTeX TabXWidth2.svg|450px|right]]}}
}}

Tabularx with rows spanning multiple columns using {{LaTeX/LaTeX|code=\multicolumn<!---->}}. The two central columns are posing as one by using the {{LaTeX/Parameter|X@{}}} option. Note that the {{LaTeX/LaTeX|code=\multicolumn<!---->}} width (which in this example is 2) should equal the (in this example 1+1) width of the spanned columns:

{{LaTeX/Example|code=
\usepackage{tabularx}
% ...

\begin{tabularx}{1\textwidth}{ {{!}}>{\setlength\hsize{1\hsize}\centering}X{{!}}>{\setlength\hsize{1\hsize}\raggedleft}X@{} >{\setlength\hsize{1\hsize}\raggedright}X{{!}}>{\setlength\hsize{1\hsize}\centering}X{{!}} } 
  \hline
Label 1 & \multicolumn{2}{>{\centering\setlength\hsize{2\hsize} }X{{!}}}{Label 2} & Label 3\tabularnewline
\hline 
  123  & 123  & 456  & 123  \tabularnewline
  \hline
  123  & 123  & 456  & 123  \tabularnewline
  \hline
\end{tabularx}
|render=
{{Dark mode invert|[[Image:LaTeX tabularx_multi.svg|450px|right]]}}
}}

In a way analogous to how new commands with arguments can be created with {{code|\newcommand}}, new column types with arguments can be created with {{code|\newcolumntype}} as follows:

{{LaTeX/Usage|code=
\usepackage{tabularx}
\usepackage[table]{xcolor} %Used to color the last column
% ...

\newcolumntype{L}[1]{>{\hsize=#1\hsize\raggedright\arraybackslash}X}%
\newcolumntype{R}[1]{>{\hsize=#1\hsize\raggedleft\arraybackslash}X}%
\newcolumntype{C}[2]{>{\hsize=#1\hsize\columncolor{#2}\centering\arraybackslash}X}%

\begin{tabularx}{\textwidth}{ {{!}} L{1} {{!}} R{0.5} {{!}} R{0.5} {{!}} C{2}{gray} {{!}} }
  \hline
  label 1 & label 2 & label 3 & label 4 \\
  \hline
  item 1  & item 2  & item 3  & item 4  \\
  \hline
\end{tabularx}
}}

where since there are 4 columns, the sum of the {{code|\hsize}}'s (1 + 0.5 + 0.5 + 2) must be equal to 4. The default value used by tabularx for {{code|\hsize}} is 1.

### The ''tabulary'' package

[http://www.ctan.org/pkg/tabulary <code>tabulary</code>] is a modified {{LaTeX/Package|tabular*}} allowing width of columns set for equal heights.
{{LaTeX/Package|tabulary}} allows easy and convenient writing of well balanced tables. 

The problem with {{LaTeX/Package|tabularx}} is that it leaves much blank if your cells are almost empty. Besides, it is not easy to have different column sizes.

{{LaTeX/Package|tabulary}} tries to balance the column widths so that each column has at least its natural width, without exceeding the maximum length.

{{LaTeX/Usage|code=
\usepackage{tabulary}
...

\begin{center}
  \begin{tabulary}{0.7\textwidth}{LCL}
    Short sentences      & \#  & Long sentences                                                 \\
    \hline
    This is short.       & 173 & This is much loooooooonger, because there are many more words.  \\
    This is not shorter. & 317 & This is still loooooooonger, because there are many more words. \\
  \end{tabulary}  
\end{center}
}}

The first parameter is the maximum width. {{LaTeX/Package|tabulary}} will try not to exceed it, but it will not stretch to it if there is not enough content, contrary to {{LaTeX/Package|tabularx}}.

The second parameter is the column disposition. Possible values are those from the {{LaTeX/Environment|tabular}} environment, plus

{| class="wikitable"
| {{LaTeX/Parameter|L}}
| left-justified balanced column
|-
| {{LaTeX/Parameter|C}}
| centered balanced column
|-
| {{LaTeX/Parameter|R}}
| right-justified balanced column
|-
| {{LaTeX/Parameter|J}}
| left-right-justified balanced column
|}

These are all capitals.

### The ''tabu'' environment

It works pretty much like {{LaTeX/Environment|tabularx}}.

Note:  ''tabu'' is currently [https://github.com/tabu-issues-for-future-maintainer/tabu/blob/master/README.md broken and unmaintained]

{{LaTeX/Usage|code=

\begin{tabu} to \linewidth {llX[2]lllXl}
% ...
\end{tabu}
}}

{{LaTeX/LaTeX|code=to \linewidth<!---->}} specifies the target width.
The {{LaTeX/Parameter|X}} parameter can have an optional span factor.

## Table across several pages

Long tables are natively supported by LaTeX thanks to the {{LaTeX/Environment|longtable}} environment, which replaces both the {{LaTeX/Environment|tabular}} and {{LaTeX/Environment|table}} environments or rather combines them into a single environment. Unfortunately, this environment does not support stretching (X columns).

The {{LaTeX/Package|tabu}} package (which is [https://github.com/tabu-issues-for-future-maintainer/tabu/blob/main/README.md no longer maintained]) provides the {{LaTeX/Environment|longtabu}} environment. It has most of the features of {{LaTeX/Environment|tabu}}, with the additional capability to span multiple pages.

LaTeX can do well with long tables: you can specify a header that will repeat on every page, a header for the first page only, and the same for the footer.

{{LaTeX/Usage|code=
\begin{longtabu} to \linewidth {lX[2]lXl}

\rowfont\bfseries H1 & H2 & H3 & H4 & H5 \\ \hline 
\endhead

\\ \hline
\multicolumn{5}{r}{There is more to come} \\
\endfoot

\\ \hline
\endlastfoot

% Content ...

}}

It uses syntax similar to {{LaTeX/Environment|longtable}}, so you should have a look at its documentation if you want to know more.

Alternatively you can try one of the following packages [http://www.ctan.org/pkg/supertabular <code>supertabular</code>] or [http://www.ctan.org/pkg/xtab <code>xtab</code>], an extended and somewhat improved version of {{LaTeX/Package|supertabular}}.

## Vertically centered images

Inserting images into a table row will align it at the top of the cell.
By using the {{LaTeX/Package|array}} package this problem can be solved.
Defining a new columntype will keep the image vertically centered.

{{LaTeX/Usage|code=
\newcolumntype{V}{>{\centering\arraybackslash} m{.4\linewidth} }
}}

Or use a parbox to center the image.

{{LaTeX/Usage|code=
\parbox[c]{1em}{\includegraphics{image.png} }

A raisebox works as well, also allowing to manually fine-tune the alignment with its first parameter.

## Professional tables

Many professionally typeset books and journals feature simple tables, which have appropriate spacing above and below lines, and almost ''never'' use vertical rules. Many examples of LaTeX tables (including this Wikibook) showcase the use of vertical rules (using "|"), and double-rules (using {{LaTeX/LaTeX|code=\hline\hline<!---->}} or "||"), which are regarded as unnecessary and distracting in a professionally published form.  The [http://www.ctan.org/tex-archive/macros/latex/contrib/booktabs/ booktabs] package is useful for easily providing this professionalism in LaTeX tables, and the [http://mirrors.ctan.org/macros/latex/contrib/booktabs/booktabs.pdf documentation] also provides guidelines on what constitutes a "good" table.

In brief, the package uses {{LaTeX/LaTeX|code=\toprule<!---->}} for the uppermost rule (or line), {{LaTeX/LaTeX|code=\midrule<!---->}} for the rules appearing in the middle of the table (such as under the header), and {{LaTeX/LaTeX|code=\bottomrule<!---->}} for the lowermost rule. This ensures that the rule weight and spacing are acceptable. In addition, {{LaTeX/LaTeX|code=\cmidrule<!---->}} can be used for mid-rules that span specified columns. The following example contrasts the use of booktabs and  two equivalent normal LaTeX implementations (the second example requires {{LaTeX/LaTeX|code=\usepackage{array}<!---->}} or {{LaTeX/LaTeX|code=\usepackage{dcolumn}<!---->}}, and the third example requires {{LaTeX/LaTeX|code=\usepackage{booktabs}<!---->}} in the preamble).

### Normal LaTeX
{{LaTeX/Example|code=
\begin{tabular}{llr}
\hline
\multicolumn{2}{c}{Item} \\
\cline{1-2}
Animal    & Description & Price (\$) \\
\hline
Gnat      & per gram    & 13.65      \\
          & each        & 0.01       \\
Gnu       & stuffed     & 92.50      \\
Emu       & stuffed     & 33.33      \\
Armadillo & frozen      & 8.99       \\
\hline
\end{tabular}
|render={{Dark mode invert|[[Image:LaTeX animal table.svg]]}}}}

### Using {{LaTeX/Package|array}}

%or \usepackage{dcolumn}
...

\firsthline
\multicolumn{2}{c}{Item} \\
\cline{1-2}

\hline

          & each        & 0.01       \\
Gnu       & stuffed     & 92.50      \\
Emu       & stuffed     & 33.33      \\

\lasthline
\end{tabular}
|render={{Dark mode invert|[[Image:LaTeX animal table with array.svg]]}}}}

### Using {{LaTeX/Package|booktabs}}

\toprule
\multicolumn{2}{c}{Item} \\

Usually the need arises for footnotes under a table (and not at the bottom of the page), with a caption properly spaced above the table. These are addressed by the [http://www.ctan.org/tex-archive/macros/latex/contrib/ctable/ ctable] package. It provides the option of a short caption given to be inserted in the list of tables, instead of the actual caption (which may be quite long and inappropriate for the list of tables). To add a legend to a table the [http://www.ctan.org/tex-archive/macros/latex/contrib/caption/ caption] package can be used. With the caption package a {{LaTeX/LaTeX|code=\caption*{...}<!---->}} statement can be added besides the

## The ''eqparbox'' package

On rare occasions, it might be necessary to stretch every row in a table to the natural width of its longest line, for instance when one has the same text in two languages and wishes to present these next to each other with lines synching up. A tabular environment helps control where lines should break, but cannot justify the text, which leads to ragged right edges. The {{LaTeX/Package|eqparbox}} package provides the command {{LaTeX/LaTeX|code=\eqmakebox<!---->}} which is like {{LaTeX/LaTeX|code=\makebox<!---->}} but instead of a {{LaTeX/Parameter|width}} argument, it takes a tag. During compilation it bookkeeps which {{LaTeX/LaTeX|code=\eqmakebox<!---->}} with a certain tag contains the widest text and can stretch all {{LaTeX/LaTeX|code=\eqmakebox<!---->}}es with the same tag to that width. Combined with the {{LaTeX/Package|array}} package, one can define a column specifier that justifies the text in all lines:comand

{{LaTeX/Usage|code=
\newsavebox{\tstretchbox}
\newcolumntype{S}[1]{%
  >{\begin{lrbox}{\tstretchbox} }%
  l%
  <{\end{lrbox}%
  \eqmakebox[#1][s]{\unhcopy\tstretchbox} }%
}
}}

See the documentation of the {{LaTeX/Package|eqparbox}} package for more details.

## The ''paracol'' package

The various tabular environments available for LaTeX are feature rich; however, they lack the ability to '''automatically page break large rows'''. The paracol package provides automatic page breaks in between rows and in certain cases can replace the tabular environment. Such situations could be common in documents that require translations and definitions, which may also includes lists.

For further detail see the documentation of the {{LaTeX/Package|paracol}} package.


## Floating with ''table''

In WYSIWYG document processors, it is common to put tables in the middle of the text. This is what we have been doing until now.
Professional documents, however, often make it a point to print tables on a dedicated page so that they do not disrupt the flow. From the point of view of the source code, one has no idea on which page the current text is going to lie, so it is hardly possible to guess which page may be appropriate for our table. LaTeX can automate this task by abstracting objects such as tables, pictures, etc., and deciding for us where they might fit best. This abstraction is called a ''float''. Generally, an object that is floated will appear in the vicinity of its introduction in the source file, but one can choose to control its position also.

To tell LaTeX we want to use our table as a float, we need to put a {{LaTeX/Environment|table}} environment around the {{LaTeX/Environment|tabular}} environment, which is able to float and add a label and caption.

{{Warning|
Please understand: you do not ''have to'' use floating tables. If you want to place your tables where they lie in your source code and you do not need any label, do not use {{LaTeX/Environment|table}} at all! This is a very common misunderstanding among newcomers.
}}

The {{LaTeX/Environment|table}} environment initiates a type of float just as the environment {{LaTeX/Environment|figure}}. In fact, the two bear a lot of similarities (positioning, captions, etc.). More information about floating environments, captions etc. can be found in [[LaTeX/Floats,_Figures_and_Captions|Floats, Figures and Captions]].

The environment names may now seem quite confusing. Let's sum it up:
* {{LaTeX/Environment|tabular}} is for the content itself (columns, lines, etc.).
* {{LaTeX/Environment|table}} is for the location of the table on the document, plus caption and label support.

{{LaTeX/Usage|code=
\begin{table}[position specifier]
  \centering
  \begin{tabular}{{{!}}l{{!}}}
    ... your table ...
  \end{tabular}
  \caption{This table shows some data}
  \label{tab:myfirsttable}
\end{table}
}}

In the table, we used a label, so now we can refer to it just like any other reference:
{{LaTeX/Usage|code=
\ref{tab:myfirsttable}
}}

The {{LaTeX/Environment|table}} environment is also useful when you want to have a
list of tables at the beginning or end of your document with the command

{{LaTeX/Usage|code=
\listoftables
}}
The captions now show up in the list of tables, if displayed.

You can set the optional parameter {{LaTeX/Parameter|position specifier}} to define the position of the table, where it should be placed. The following characters are all possible placements. Using sequences of it define your "wishlist" to LaTeX.

{| class="wikitable"
|-
| {{LaTeX/Parameter|h}}
| where the table is declared ('''h'''ere)
|-
| {{LaTeX/Parameter|t}}
| at the '''t'''op of the page
|-
| {{LaTeX/Parameter|b}}
| at the '''b'''ottom of the page
|-
| {{LaTeX/Parameter|p}}
| on a dedicated '''p'''age of floats
|-
| {{LaTeX/Parameter|!}}
|override the default float restrictions. E.g., the maximum size allowed of a {{LaTeX/Parameter|b}} float is normally quite small; if you want a large one, you need this {{LaTeX/Parameter|!}} parameter as well.
|-
|}

Default is {{LaTeX/Parameter|tbp}}, which means that it is by default placed on the top of the page. If that's not possible, it's placed at the bottom if possible, or finally with other floating environments on an extra page.

You can force LaTeX to use one given position. E.g. {{LaTeX/Parameter|[!h]}} forces LaTeX to place it exactly where you place it (Except when it's really impossible, e.g you place a table ''here'' and this place would be the last line on a page). Again, understand it correctly: it urges LaTeX to put the table at a specific place, but it will not be placed there if LaTeX thinks it will not look great. If you really want to place your table manually, do not use the {{LaTeX/Environment|table}} environment.

Centering the table horizontally works like everything else, using the {{LaTeX/LaTeX|code=\centering<!---->}} command just after opening the {{LaTeX/Environment|table}} environment, or by enclosing it with a {{LaTeX/Environment|center}} environment.

## Using spreadsheets and data analysis tools

For complex or dynamic tables, you may want to use a spreadsheet. You might save lots of time by building tables using specialized software and exporting them in LaTeX format. The following plugins and libraries are available for some popular software:
* [http://calc2latex.sourceforge.net/ calc2latex]: for LibreOffice and OpenOffice.org Calc spreadsheets,
* [http://www.ctan.org/tex-archive/support/excel2latex/ excel2latex]: for Microsoft Office Excel,
* [https://github.com/TheChymera/matrix2latex matrix2latex]: for Python and MATLAB,
* [http://pandas.pydata.org/pandas-docs/stable/generated/pandas.DataFrame.to_latex.html pandas]: pandas DataFrame's have a method to convert data they contain to latex,
* [http://rubygems.org/gems/latex-tools latex-tools]: a Ruby library,
* [http://cran.r-project.org/web/packages/xtable/index.html xtable]: a library for R,
* [http://orgmode.org/ org-mode]: for Emacs users, org-mode tables can be used inline in LaTeX documents, see [https://www.gnu.org/software/emacs/manual/html_node/org/A-LaTeX-example.html] for a tutorial.
* [http://emacswiki.org/emacs/AlignCommands Emacs align commands]: the align commands can clean up a messy LaTeX table.
* [http://truben.no/latex/table/ Online Table generator for LATeX]: An online tool for creating simple tables within the browser. LaTeX format is directly generated as you type.
* [http://www.tablesgenerator.com/ Create LaTeX tables online ]: Online tool.

However, copying the generated source code to your document is not convenient at all. For maximum flexibility, generate the source code to a separate file which you can input from your main document file with the {{LaTeX/LaTeX|code=\input<!---->}} command.
If your spreadsheet supports command-line, you can generate your complete document (table included) in one command, using a Makefile for example.

See [[LaTeX/Modular Documents|Modular Documents]] for more details.

## Need more features?

Have a look at one of the following packages:

* [http://www.ctan.org/pkg/hhline <code>hhline</code>]:   do whatever you want with horizontal lines
* [http://www.ctan.org/pkg/array <code>array</code>]:    gives you more freedom on how to define columns
* [http://www.ctan.org/pkg/colortbl <code>colortbl</code>]: make your table more colorful
* <code>[https://ctan.org/pkg/threeparttable threeparttable]</code> makes it possible to put footnotes both within the table and its caption
* [http://www.ctan.org/pkg/arydshln <code>arydshln</code>]: creates dashed horizontal and vertical lines
* [http://www.ctan.org/pkg/ctable <code>ctable</code>]: allows for footnotes under table and properly spaced caption above (incorporates booktabs package)
* [http://www.ctan.org/pkg/slashbox <code>slashbox</code>]: create 2D tables with the first cell containing a description for both axes. Not available in Tex Live 2011 or later. 
* <code>[https://ctan.org/pkg/diagbox diagbox]</code>: compatible to <code>slashbox</code>, come with Tex Live 2011 or later
* [http://www.ctan.org/pkg/dcolumn <code>dcolumn</code>]: decimal point alignment of numeric cells
* [http://www.ctan.org/pkg/rccol <code>rccol</code>]: advanced decimal point alignment of numeric cells with rounding
* [http://www.ctan.org/pkg/numprint <code>numprint</code>]: print numbers, in the current mode (text or math) in order to use the correct font, with separators, exponent and/or rounded to a given number of digits. tabular(*), array, tabularx, and longtable environments are supported using all features of numprint
* [http://www.ctan.org/pkg/spreadtab <code>spreadtab</code>]: spread sheets allowing the use of formulae
* [http://ctan.org/tex-archive/macros/latex/contrib/siunitx <code>siunitx</code>]: alignment of tabular entries
* <code>[https://www.ctan.org/pkg/pgfplotstable pgfplotstable]</code>: loads, rounds, formats and postprocesses numerical tables, e.g. by importing the data directly from .csv (comma-separated value) files instead of manually writing the whole tables in LaTeX code. Programs such as Excel, LibreOffice Calc etc. can export data sheets as .csv files.
